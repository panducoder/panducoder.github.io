Host once, track everywhere: a learning content controller

Keep course content in one place, drop a tiny stub into any LMS, and get results back centrally.

01The problem

Training content shipped as packages into dozens of customer LMSs is hard to update, license, version and track. A content controller keeps the content in one place while results flow back to both the LMS and a central database.

02How it works
  1. Import and validate. Admins import a course package; a parser validates SCORM 1.2/2004, AICC, cmi5, xAPI and LTI packages.
  2. Build a stub. A small per-standard stub package is generated for upload to any LMS.
  3. Launch and stream. When a learner launches the stub, the runtime serves the player, signed content URLs and the tracking endpoints.
  4. Server decides. Roll-up is server-authoritative: a browser that claims a pass on a failing score is recorded as a fail.
  5. Run it. Accounts, licensing, versions, reports, webhooks, SSO, an automation API and PII anonymisation.
03Decisions & trade-offs

04My role

I built it end to end as a large monorepo with 90+ logged decisions, a threat model, an OpenAPI spec and browser tests against real LMS standards.

05Result

Working platform with tests across SCORM 1.2, AICC, cmi5 and LTI; remaining gaps documented.
